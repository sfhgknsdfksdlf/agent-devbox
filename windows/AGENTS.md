# windows/ — WSL installer & data-disk helpers

## OVERVIEW
PowerShell that imports a released rootfs as a WSL distro and wires a persistent data disk. The ONLY install entry is the raw `install.ps1` one-liner; there are no `.cmd`/`.bat` bootstrappers. No Docker needed on Windows.

## FILES
| File | Role |
|---|---|
| install.ps1 | **Sole entry**, served from `main` (`irm .../windows/install.ps1 \| iex`). Prompts release / variant / code ref (`?` lists branches) but NEVER the channel: `$Channel` = `beta` iff `$Ref -ne 'main'` else `stable`; `$Ref` = `-Ref` > `$env:AGENT_DEVBOX_REF` > prompt > `main`, and `irm\|iex` cannot see the URL branch (branch installs must pass `-Ref`/env). The splat passes `Channel`, never `-Ref`. Self-elevates once (freshly written copy → `RemoteSigned`, log relay), fetches the 5 siblings from the SAME `-Ref` (raw source, NOT the Release), verifies them against `windows/SHA256SUMS` before dot-sourcing, runs the preflight + installer; rootfs parts come from the Release. UTF-8 **without** BOM. |
| install-agent-devbox.ps1 | The installer: Chinese 10-step banner; `[2/10]` disk check BEFORE download; host-arch selection (`rootfs-$Variant-$Arch`), Windows 10 ARM64 rejection, pre-mkfs `uname -m` probe; tiered import; `-Channel` (`stable\|beta`, default `stable`; forwarded in its own UAC argv, never `-Ref`) → `Get-AgentDevboxChannelIdentity` (`-beta` distro/dir/label/WT GUID; no `$VariantMap`), explicit `-InstallDir` never suffixed; ownership valve (`data.vhdx`/`ext4.vhdx` + `<dir>\.agent-devbox-channel`, missing = legacy stable; mismatch throws before its UAC); `New-VHD` probe → diskpart fallback → non-empty `data.vhdx`; attach + ACL + `datadisk-init.sh <label>` (non-zero = FATAL, keeps `data.vhdx`) + 6-key `/etc/agent-devbox.conf` (`DATA_LABEL` included) + one direct attach (NO scheduled task; unregisters legacy `agent-devbox*-mount-datadisk` tasks) + copy the manual `.cmd` helpers; writes the fixed-GUID WT profile fragment BEFORE the import and removes WSL's stale fragment; persistent transcript in the InstallDir; never prints the password. |
| wsl-ensure.ps1 | Dot-sourced preflight + shared helpers: `Ensure-Wsl`/`Test-WslInstalled`/mirrored networking, `Normalize-ReleaseTag`, `Quote-NativeArg`, `Join-Parts`, `Get-FreeDiskSpaceBytes` (managed `DriveInfo`), `Get-ZstdUncompressedSize*` + `Assert-DiskSpace` (managed `HttpClient` Range), `Invoke-WslImportStream`, `Save-Download` (managed `HttpClient`), `Get-AgentDevboxDownloadHelperPath`, `Get-ZstdExe` (thin wrapper), sidecar read/write, `Get-FileSha256`, `ConvertFrom-Sha256Sums`, `Format-NativeOutput`, `Clear-StaleImportArtifacts`, `Assert-DistroReady`, `ConvertTo-AgentDevboxArch`, `Get-AgentDevboxHostArch`, `Get-AgentDevboxChannelIdentity` (fixed 4 rows: distro / InstallDir / label+mount name / WT Terminal+Hide GUIDs per agents\|core × stable\|beta). |
| wsl-ensure-downloads.ps1 | **Lazily loaded** (definitions only): `Install-WslUi` (wsl-ui NSIS) + `Get-ZstdExeFromRelease` (pinned zstd for Tier 3). Dot-sourced ONLY in `Ensure-Wsl`'s wsl-ui branch and `Get-ZstdExe`; the happy path never loads it. **AV-sensitive — see PITFALLS.** |
| mount-datadisk.cmd | Manual attach (pure batch, copied into the InstallDir; **no PowerShell, no UAC**): no args = `<InstallDir>\data.vhdx` with `--bare`; positional `<vhdx>` overrides the path; 3 attempts, logs `datadisk-attach.log`, exits with wsl's real code. |
| unmount-datadisk.cmd | Manual detach (pure batch, copied into the InstallDir; no PowerShell, no UAC): `wsl --unmount "\\?\<vhdx>"`; captures wsl output (`WSL_UTF8` NOT set — it breaks `--unmount`), treats `DetachDisk/ERROR_FILE_NOT_FOUND` / `0x80070002` as already detached (`[INFO]`, exit 0), logs the raw exit + output to `datadisk-attach.log`, and keeps real failures non-zero. |

## CONVENTIONS
- `$ErrorActionPreference='Stop'`. CI AST-parses every file; ps-lint also enforces AV hygiene (`wsl-ensure.ps1` has no `TypeDefinition`/`DllImport`/`HttpWebRequest`/`GetResponseStream`, does not define `Install-WslUi`, keeps `Get-AgentDevboxDownloadHelperPath`; `install.ps1` has no `irm`/`iex`/`Bypass` tokens) and the installer invariants (disk check first, interactive-only upgrade prompt before any WSL config change and before the disk check, streaming import, elevation uses `-Wait`).
- **Encoding:** `install.ps1` UTF-8 **without** BOM (a BOM survives an in-memory fetch as U+FEFF and breaks PS 5.1 parsing); every other `*.ps1` UTF-8 **with** BOM (PS 5.1 `-File` reads BOM-less as ANSI → garbled Chinese); `.cmd` ASCII + CRLF.
- **Remote text = `Invoke-WebRequest -OutFile` then `[IO.File]::ReadAllText`**, never `.Content` (PS 5.1 may return `byte[]` → zero manifest entries → bare exit code 1).
- **Staging:** scripts under `%LOCALAPPDATA%\agent-devbox` (never `%TEMP%`); `install.ps1` uses a per-run `run-<rand>` dir + temporary relay log; the installer's real transcript is `<InstallDir>\agent-devbox-install-<ts>.log`. Only the wsl-ui scratch dir uses `GetTempPath()` (the tripwire forbids it in the entry/installer only).
- **Execution policy:** `install-agent-devbox.ps1` keeps `Bypass` (MOTW risk on extracted files); `install.ps1`'s freshly written elevated child uses `RemoteSigned`.
- **Log relay:** the elevated window writes `-LogPath` (+ `$LogPath.rc`, and `$LogPath.err` for pre-installer failures); the ORIGINAL window waits, echoes the log/`失败原因`, and never relies on the exit code alone.
- **Release QA (manual, real 5.1 console):** run one interactive install with `Start-Transcript`; type a password at the prompt and confirm the transcript contains neither the typed value nor `PASEO_PASSWORD=` (the `-AsSecureString` path needs a real console, so it cannot be automated here).
- **Secrets:** never print `PASEO_PASSWORD`; it lives in `/etc/agent-devbox.conf` and `/mnt/<DATA_MNTNAME>/.paseo-password` (mode 600, survives upgrades; stable `devbox-data` / beta `devbox-data-beta`). Interactive entry uses `Read-Host -AsSecureString` (a plain `Read-Host` echoes into the transcript). Read-back of an existing password crosses native stdout as **base64** and is decoded as UTF-8 (native stdout is OEM-decoded). Transcript starts only after `$InstallDir` exists and is stopped before copying. Printed native failure output goes through `Hide-SecretText` first.
- **Interaction:** all UI text Chinese; pickers = Enter/`latest`/`b`(newest beta)/tag, variant Enter/`c`, ref Enter/`?`/name. The CHANNEL is never prompted: `beta` is automatic from `$Ref -ne 'main'`; the `b`/`beta` release picker only selects the newest `beta-*` Release tag (≠ channel). The upgrade confirmation lives in `Confirm-Upgrade` (`wsl-ensure.ps1`); `install.ps1` calls it BEFORE `Ensure-Wsl`/`Set-MirroredNetworking`, and the installer calls it for direct invocation. An existing distro prompts ONCE only on an interactive console: Enter = upgrade, `n` = cancel, one re-ask then cancel. `-Yes`/`-KeepExisting`/`-UpgradeConfirmed`/redirected input skip the prompt (upgrade). Cancel exits 0 before any download/unregister/WSL-config change. Hold the elevated window ~10 s only when `-not $Yes -and [Environment]::UserInteractive`.
- **Disk math:** `required = base + 2 GiB + max(3 GiB, 10% of base)`; streaming uses `base = C + V` (compressed + uncompressed×1.05), uncompressed from the zstd frame header (local byte read or an 18-byte Range request).
- **Import tiers:** Tier 1 stream the parts into `wsl --import - ` (WSL2 bsdtar decodes zstd) → Tier 2 `Join-Parts` + import the `.tar.zst` → Tier 3 pinned `zstd.exe` → `.tar`. Happy path never downloads `zstd.exe`. **Tier 3 is x64-only**: ARM64 uses Tier 1/Tier 2 and never fetches `zstd.exe`; the skip path must NOT set `ContentSuspect` and keeps the parts/sidecars for a retry. Never pipe tier output to `Out-Null`.
- **Download identity:** a partial is reusable only when `<InstallDir>\.agent-devbox-download\<part>.meta` matches (URL + strong ETag + length + SHA256); resume sends `Range` + **`If-Match`** (GitHub/Azure ignore `If-Range`); `412`/ignored Range/`Content-Range` mismatch restarts from zero; after close the length must equal `-ExpectedBytes` and/or the server total, then `-Sha256`. On failure remove this run's parts + sidecars.
- **Script identity:** all 6 scripts are verified with `Get-FileHash` before any dot-source; mismatch → one re-download → fatal. Manifest exists but incomplete → fatal. Only a **missing** manifest is bypassable with `-AllowUnverifiedScripts`. `wsl-ensure-downloads.ps1` is the one OPTIONAL entry (missing = warning + degraded wsl-ui/Tier 3).
- **Channels:** `Get-AgentDevboxChannelIdentity` is the ONLY 4-row table (agents|core × stable|beta) for distro / InstallDir / label+mount name / WT fragment GUIDs; the installer has no `$VariantMap` and an explicit `-InstallDir` is never suffixed. Stable+beta coexist (distinct distro/dir/disk/password/WT fragment+GUID); `%LOCALAPPDATA%\agent-devbox` staging is shared (per-run dir/log names), while `.wslconfig` / mirrored networking / `wsl --shutdown` stay host-global. Same-channel agents/core disks are interchangeable, cross-channel are not.
- **Data disk:** `New-VHD` (or diskpart, exit codes checked) → non-empty `data.vhdx` → `wsl --mount --vhd --bare` → `datadisk-init.sh <label>` (non-zero = FATAL, keeps `data.vhdx`) → UUID → `wsl --unmount`. Conf keys (6): `DATA_VHDX`, `DATA_UUID`, `DATA_LABEL`, `PASEO_PASSWORD`, `DATA_MNTNAME`, `DATA_DISTRO`; label == mount name: `devbox-data` (stable) / `devbox-data-beta` (beta, 16 chars = ext4 limit); guest precedence `AGENT_DEVBOX_DATA_LABEL` > conf `DATA_LABEL` > `devbox-data`. The installer resolves the data-disk UUID by the channel label before falling back to the old conf UUID (logging the swap), so an upgrade with a copied variant disk reads the password from the right disk. There is **no scheduled task** of any kind: the installer attaches the disk once itself and unregisters legacy `agent-devbox*-mount-datadisk` tasks left by older versions. The manual repair entry is the pure-batch `mount-datadisk.cmd` (direct `wsl.exe --mount --vhd <vhdx> --bare`, 3 attempts, `datadisk-attach.log`, wsl's real exit code; no `-EncodedCommand` wrapper, which always exited 0 and hid attach failures). The installer also asserts the NEW boot-log lines (`tail -n +N` -> `boot complete`, `boot failed` fails immediately) after the restart; `wsl -d` sessions may not see the boot session's mounts, so `findmnt` alone is not evidence. The WT repair runs BEFORE that assert, so a failed assert can never leave stale profile GUIDs. `wsl-boot.sh` attaches the VHDX itself on every start (one bounded `wsl.exe --mount --vhd --bare`, skipped when already attached), then `blkid -t UUID=` (fallback channel label) + `mount -t ext4`; it must never call `schtasks` / `wsl -d` / `--unmount`. Interactive `wsl -d` / wsl-ui login shells are covered by `config/profile.d/zz-agent-devbox-session-mount.sh` → `wsl-session-mount.sh` (re-mounts the same ext4 RW + binds `/home /root /workspace` in the session namespace; idempotent; never attaches/unmounts/formats), and the installer's closing hint names it; `findmnt` alone is still not boot-verification evidence, but the normal interactive path now shows the disk.
- **Import diagnostics:** `Format-NativeOutput` on failure; `Clear-StaleImportArtifacts` deletes a leftover `ext4.vhdx` only when `wsl -l -q` exited 0 AND the distro is absent; `Assert-DistroReady` re-checks registration and unregisters a partial one, mentioning the per-user/UAC caveat.

## PITFALLS (hard-earned — do NOT repeat)
**火绒 `HEUR:TrojanDownloader/PS.NetLoader`**
- Symptom: `wsl-ensure-downloads.ps1` deleted mid-install → elevated child dies → original window shows only `安装失败（退出码 1）`, no installer log.
- Cause: PS 5.1 `Invoke-WebRequest -OutFile` + running the fetched `.exe` is the malware downloader fingerprint; **`-UseBasicParsing`** (skip the IE engine — what every loader adds) pushes it over the line. Huorong scores statically AND via AMSI/PSET, so re-wording does not help.
- Evidence (identical bytes): `0742690` fine · `73a1a03` (token in 2 calls) quarantined · rewrite (IWR removed, token in a **comment**) quarantined again.
- Rules: no such token in that helper, comments included (tripwired). `install.ps1` may keep it for sibling downloads — do not copy it into the helper. Fix IWR hangs structurally (winget/manual), never by re-adding the flag. `.ps1` signing does NOT help. Fallback: preflight `1` (no wsl-ui); report to `bbs.huorong.cn/forum-44-1.html` / `seclab@huorong.cn` (zip password `infected`).

**PowerShell 5.1 ≠ pwsh 7**
- `.Content` may be `byte[]` → use `-OutFile` + `ReadAllText`.
- `Join-Path A B C` is PS 7 only → nest two calls.
- Native stderr under `EAP=Stop` becomes terminating → `Invoke-Native`.
- Assigning a MISSING property on a `ConvertFrom-Json` object throws → `Add-Member -Force`. WT ships a **duplicate** `agent-devbox-core` profile with no `commandline`; the old `$p.commandline = …` aborted the whole repair (`agent-devbox-install-20261021-011500.log:67`), so the stale GUID survived → wsl-ui's `wt -p` hit `WSL_E_DISTRO_NOT_FOUND` while `wsl -d` still worked.
- `Sort-Object -Property` over a `List[object]`/array of Hashtables reorders deterministically (measured 0,1,2,3 -> 2,3,0,1 on 5.1.26100.2161; pwsh 7 differs). Use `Sort-Object { [int]$_.Index }` or plan order. Gate: `powershell -File tests/powershell/ps51-order.ps1`.
- `#Requires` in `irm | iex` is fine, but pwsh 7 green proves nothing for 5.1 — only the ps-lint 5.1 run counts.
- A `'...' -f` composite format containing bash `${VAR}` / `{ ...; }` needs `${{VAR}}` / `{{ ...; }}`; the 2026-10-28 password write threw `FormatException` and never wrote the file. Test by **formatting the real literal**, not by grepping its source.
- PS 5.1's `$OutputEncoding` defaults to `us-ascii`, and native **stdout** is decoded with `[Console]::OutputEncoding` (OEM). `Invoke-Native` sets the **script-scope** `$OutputEncoding` to UTF-8 (no BOM) for the `InputText` pipe and restores it (a function-local assignment is ignored — measured). Guest scripts must not print Chinese (the ready line is printed by PowerShell).
- stdin scripts end with `# end` (absorbs PS 5.1's trailing CRLF); internal CRLF is not normalized, they must not end in a continuation/heredoc, and the native stdin pipe is bounded so keep them small.

**ARM64 / WSL 架构**
- A 32-bit (WOW64) shell reports `x86`, and an **x64-emulated PowerShell on ARM64 reports `AMD64`**, while the machine is ARM64. `wsl-ensure-downloads.ps1` used to read the process env alone; it now calls `Get-AgentDevboxHostArch` (Machine-scope registry value wins, unknown throws).
- `wsl --import` does **not** validate architecture. After import and BEFORE `datadisk-init.sh` the installer runs `uname -m`; a mismatch or `Exec format error` unregisters the new distro, deletes only `ext4.vhdx`, and keeps `data.vhdx` + the parts.
- ARM64 import has no Tier 3: never fetch `zstd.exe` there (the published binary is win64-only), and never hard-code `rootfs-$Variant-amd64` (the stem is `rootfs-$Variant-$Arch`).
- Skipping Tier 3 is not evidence of corruption: never set `ContentSuspect`, keep the parts and sidecars so a re-run re-verifies SHA256 and retries.

**通道所有权阀 / 数据盘**
- 目录含 `data.vhdx` **或** `ext4.vhdx` 即属于一个通道，标记为 `<dir>\.agent-devbox-channel`（缺失 = legacy stable）。beta + `-InstallDir` 指向另一通道的盘时必须在任何改动前 throw（installer 自身 UAC 之前；`irm|iex` 时入口已提权），绝不格式化对方的盘或把对方的 UUID/密码写进 `$ConfPath`。
- `datadisk-init.sh` 非零退出即 FATAL（保留 `data.vhdx`），否则本 conf 可能记录另一通道的盘。
- beta 安装拒绝 `/usr/local/bin/wsl-boot.sh` 缺 `DATA_LABEL` 的旧 rootfs（否则会回退到共享的 `devbox-data` 标签）：明确报错并提示改用 `-ReleaseTag beta`，保留 `data.vhdx`；stable 不受影响。
- **wsl --unmount 未附加 = ERROR_FILE_NOT_FOUND**: after a Windows reboot the attach is gone; the helper must match the UTF-16LE/stderr token (redirected output is UTF-16, so use `findstr /R /C:"E.R.R.O.R..."` plus the UTF-8 literal) on a FRESH `%TEMP%` capture, never `datadisk-attach.log` (stale lines). **Never set `WSL_UTF8=1`**: it makes `--unmount` fail with `ERROR_INVALID_NAME` even for an attached disk, and `ERROR_INVALID_NAME` cannot be treated as success (in-use also returns it). A missing VHDX path stays a non-zero error.

**Guest bash scripts never travel in argv（2026-10-28）**
- PS 5.1 wraps a native argument in quotes but does not escape inner `"`; `wsl.exe` then splits the script at the next space. The data-disk password write was truncated at `$(cat ` (bash exit 2) and the password leaked into the log through stderr. Use `Invoke-WslBashScript` (`bash -ls`, script on stdin, trailing `# end` so PS 5.1's CRLF does not become a `$'\r'` command / exit 127); mask secrets in any printed failure output.
- A deleted distro's `Fragments\AgentDevbox\<distro>.json` keeps a `startingDirectory` under `\\wsl$\<distro>\root`; WT caches it and then fails new tabs with `0x8007010b`. `Write-AgentDevboxTerminalProfile` prunes fragments whose distro is not in `wsl -l -q` (never the one being written, which is legitimately unregistered before import).

**Windows checkout 默认 CRLF（2026-10-24 CI ps-lint）**
- windows-latest 的 Git for Windows 默认 `core.autocrlf=true`，`actions/checkout` 不覆盖；根 `.gitattributes` 用 `* text=auto eol=lf` 强制 LF，`.cmd` 用 `-text -eol` 保持 blob/raw 的 CRLF（`text eol=crlf` 会把 blob 变 LF，破坏 raw 下载与 `SHA256SUMS`）。
- 读文件后的多行断言不要用裸 `$`（.NET 的 `$` 不匹配 `\r\n`），用 `\r?$`；`\s*$` 会吞换行，不可靠。

## ANTI-PATTERNS
- NEVER build a `cmd /c copy /b "..."` string (quote/`$()` escaping) — use `Join-Parts`.
- NEVER add a second install entry (`.cmd`/`.bat`) or a second elevation path.
- NEVER move `Assert-DiskSpace` after the download, and NEVER make the happy path fetch `zstd.exe`.
- NEVER add a second upgrade-confirmation prompt or a `[Y/n]` prompt: the confirmation lives in `Confirm-Upgrade` (`wsl-ensure.ps1`), and `install.ps1` may only call it, and must call it BEFORE `Ensure-Wsl`/`Set-MirroredNetworking` so cancel cannot change `.wslconfig` or shut WSL down. The installer calls the same helper for direct invocation. The install-dir prompt is the ONE allowed direct `Read-Host`: it runs BEFORE the UAC hand-off and BEFORE `Confirm-Upgrade`, and must not prompt again when `-InstallDir` is passed. Enter is the only affirmative. NEVER make the AV prompt a `Read-Host` or sleep unconditionally.
- NEVER assign a possibly-missing JSON property directly (`$p.commandline = …`): WT profiles may lack it, and one throw aborts the repair for every profile. Use `Add-Member -Force`.
- NEVER leave a repaired WT profile without `startingDirectory`: null/absent means "inherit the launch location" (`%WINDIR%\System32` when started from the Start menu). Use the documented `\\\\wsl$\\<distro>\\root` form — `~` is NOT documented — and never override a user's value.
- NEVER edit WT `settings.json` without a timestamped backup + re-parse, and NEVER touch profiles outside `agent-devbox*` / `source=Microsoft.WSL`.
- NEVER copy an active transcript, and NEVER start it before `$InstallDir` exists.
- NEVER probe `New-VHD` with a bare `try/catch`; NEVER ignore diskpart exit codes.
- NEVER shell out for downloads (`curl.exe` in `Save-Download`) — managed `System.Net.Http` only (proxy/PAC, progress, tripwired).
- NEVER let the boot script call `schtasks.exe` / `wsl -d` / `--unmount` (boot loop); its only Windows call is the one bounded `wsl.exe --mount --vhd --bare` attach.
- NEVER delete `<InstallDir>\ext4.vhdx` while `wsl -l -q` lists the distro; NEVER format an existing data disk.
- NEVER pipe `wsl --import` / `zstd.exe` output to `Out-Null`.
- NEVER accept end-of-stream or a matching length as proof: length gate + identity sidecar + `SHA256SUMS` decide.
- NEVER put the sidecar next to the parts (`<part>.meta` matches the `rootfs-*.part-*` glob); NEVER resume with `If-Range`.
- NEVER dot-source a sibling before its `SHA256SUMS` check; NEVER bypass a partial/mismatched manifest with `-AllowUnverifiedScripts`.
- NEVER stage or execute installer scripts from `%TEMP%`.
- NEVER add `Add-Type -TypeDefinition` / `DllImport` / `HttpWebRequest` / `GetResponseStream` to `wsl-ensure.ps1`, and NEVER put a download-and-execute helper back into it (`Get-ZstdExe` stays a thin wrapper).
- NEVER add a BOM to `install.ps1`, strip it elsewhere, add non-ASCII to `.cmd`, or change `.cmd` to LF.
- The interactive shell user is root; the daemon runs as non-root `paseo`.
