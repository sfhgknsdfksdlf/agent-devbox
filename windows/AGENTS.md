# windows/ — WSL installer & launchers

## OVERVIEW
PowerShell that imports the released rootfs as a WSL distro and wires up a persistent data disk. No Docker needed on Windows.

## WHERE TO LOOK
| File | Role |
|---|---|
| install.cmd | **recommended local entry** (ASCII/CRLF bootstrapper): fetches the installer scripts (`wsl-ensure.ps1`, `wsl-ensure-downloads.ps1`, `install-agent-devbox.ps1`) from the project SOURCE (`raw.githubusercontent.com/<repo>/main/windows`) into `%LOCALAPPDATA%\agent-devbox\bootstrap-<rand>` via PowerShell `Invoke-WebRequest` (so the Windows system proxy / VPN is honoured; the curl CLI is proxy-blind), launches `install-agent-devbox.ps1` (forwards `%*`; optional `AGENT_DEVBOX_RELEASE_TAG`), removes the stage on every path, and always `pause`s. The Release is used ONLY for the rootfs payload |
| install-agent-devbox.ps1 | full installer: Chinese 10-step banner (step `[2/10]` is the disk-space pre-check); tiered import (stream into `wsl --import -` → merge → `zstd.exe`); post-import registration assert; **per-variant map** (agents → distro `agent-devbox` / dir `D:\WSL\agent-devbox` / task `agent-devbox-mount-datadisk`; core → `agent-devbox-core` / `D:\WSL\agent-devbox-core` / `agent-devbox-core-mount-datadisk`); create/attach VHDX + fix ACLs + init with ext4 label `devbox-data` + write the 5-key `/etc/agent-devbox.conf` (`DATA_MNTNAME`=`devbox-data`) + **always** register the hidden attach-only logon task (`-NoTask` skips) + copy the `mount-datadisk.*` / `unmount-datadisk.*` helpers into the InstallDir; asks core-vs-agents when interactive; stages its parent log under `%LOCALAPPDATA%\agent-devbox`; dot-sources `wsl-ensure.ps1` |
| install.ps1 | **legacy** raw in-memory web entry: the script is fetched and executed in memory by the PowerShell host; asks the release + image variant when interactive, self-elevates (log-relay), fetches the installer scripts from the project SOURCE (`main`) — not the Release — runs the preflight + installer, and pulls the rootfs from the Release. **Not shipped in the release zip**; the recommended local entry is `install.cmd`. UTF-8 **without** BOM (see below) |
| import-distro.ps1 | import-only path (no data disk): the same tiered import; dot-sources `wsl-ensure.ps1` |
| wsl-ensure.ps1 | dot-sourced preflight **and** shared helpers: `Ensure-Wsl`/`Test-WslInstalled`/mirrored-networking, plus `Normalize-ReleaseTag`, `Resolve-YesNoDefault`, `Test-ZstdBanner`, `Get-NativeZstdSupport`, `Quote-NativeArg`, `Join-Parts`, `Get-FreeDiskSpaceBytes` (managed `System.IO.DriveInfo`, no P/Invoke), `Get-ZstdUncompressedSize`/`FromBytes`/`FromUrl` (managed `HttpClient` Range, no raw `HttpWebRequest`), `Get-RequiredDiskBytes`, `Test-DiskSpace`, `Assert-DiskSpace`, `Invoke-WslImportStream`, `Save-Download` (curl.exe with `-C -` resume + retries; curl verifies Content-Length and exits non-zero on a short read, so a truncated part is retried instead of kept; Invoke-WebRequest fallback), `Get-AgentDevboxDownloadHelperPath` (resolves the lazily loaded download helper), `Get-ZstdExe` (thin wrapper, same name/signature; the download+expand body lives in `wsl-ensure-downloads.ps1`), `Assert-DistroReady` |
| wsl-ensure-downloads.ps1 | **lazily loaded** download-and-execute helper (UTF-8 with BOM, definitions only): owns `Install-WslUi` (wsl-ui NSIS download + silent install) and `Get-ZstdExeFromRelease` (pinned `zstd.exe` for the Tier 3 fallback). Resolved by `Get-AgentDevboxDownloadHelperPath` and dot-sourced only inside `Ensure-Wsl`'s wsl-ui branch and the `Get-ZstdExe` wrapper, so the happy path never loads it |
| agent-devbox.bat / agent-devbox-core.bat | thin **non-interactive** launchers (each passes its own `-Variant`); self-elevate via `fltmc` + `Start-Process -Verb RunAs` on the `.bat` itself; always `pause` at the end (success or failure) |
| mount-datadisk.cmd / mount-datadisk.ps1 | manual attach helper (ships in the zip, copied into the InstallDir): no args = attach `<InstallDir>\data.vhdx` (`--bare`); `-Vhdx "D:\other\x.vhdx"` = attach that VHDX (`--bare`); plus `-Name mydisk` = attach + auto-mount at `/mnt/wsl/mydisk` (`--type ext4 --name mydisk`). Self-elevates once via `Start-Process -Verb RunAs` |
| unmount-datadisk.cmd / unmount-datadisk.ps1 | manual detach helper (ships in the zip, copied into the InstallDir): `wsl --unmount "\\?\<vhdx>"`, self-elevates once |

## CONVENTIONS
- `$ErrorActionPreference='Stop'`; CI AST-parses every `windows/*.ps1` (ps-lint job). The same job enforces AV hygiene: `wsl-ensure.ps1` must not contain `TypeDefinition`, `DllImport`, `HttpWebRequest` or `GetResponseStream`, must not define `Install-WslUi` (it lives in `wsl-ensure-downloads.ps1`), and must keep `Get-AgentDevboxDownloadHelperPath`; `install.ps1` must not contain the legacy in-memory fetch/execute tokens or `-ExecutionPolicy Bypass`.
- **Encoding/BOM policy (CI ps-lint enforces):** `install.ps1` is UTF-8 **WITHOUT** a BOM — an in-memory fetch returns the body as a string and a BOM survives as U+FEFF, which breaks parsing on PowerShell 5.1. Every other `windows/*.ps1` (read via `-File`) is UTF-8 **WITH** a BOM — PS 5.1 reads a BOM-less file as ANSI and would garble the Chinese. The `.bat` launchers are ASCII-only, and `.cmd` files are ASCII + CRLF (cmd reads a BOM-less file as ANSI, and CRLF avoids its line-ending edge cases). Chinese lives in the `.ps1`.
- **Staging:** installer scripts and downloads stage under `%LOCALAPPDATA%\agent-devbox`, never `%TEMP%` (the download-and-execute shape from a temp directory is what Huorong scored). `install.ps1` uses a per-run `run-<rand>` work dir plus `install-<rand>.log`; `install-agent-devbox.ps1` writes `agent-devbox-install-<ts>.log`; `install.cmd` uses `bootstrap-<rand>`. Per-run dirs and logs are removed on success and failure; the base directory persists (empty).
- **Execution policy:** `install.cmd` and `install-agent-devbox.ps1` keep `-ExecutionPolicy Bypass` because Explorer-extracted files may carry Mark-of-the-Web, which `RemoteSigned` would block. `install.ps1`'s elevated child is freshly written by the parent (no Mark-of-the-Web), so it uses `RemoteSigned` instead of the stronger signal.
- All user-facing installer text is **Chinese**; `install-agent-devbox.ps1` prints a 10-step banner (`[1/10] 检查运行环境` … `[2/10] 检查磁盘空间` … `[10/10] 注册开机自动挂载计划任务` + `[完成] 重启发行版`). CI's ps-lint also enforces the BOM rules and the installer invariants (disk check present, `[Y/n]` not `[y/N]`, streaming import present, elevation uses `-Wait`).
- Elevates once via UAC. `install-agent-devbox.ps1` re-invokes itself with the same params; the elevated window writes its full transcript (`-LogPath`, plus a `<log>.rc` exit-code file) and the **original** window waits, then echoes the whole log plus a final summary and exit code, so the result is visible where the user started. The `.bat` launchers re-launch the `.bat` elevated and always `pause` at the end (success or failure).
- Image picker (Chinese): a local run through `install.cmd`, the legacy in-memory web entry, or `install-agent-devbox.ps1` directly asks core vs agents when interactive (Enter = 完整版/多助手 `agents`, `c`/`core` = 精简版 `core`). The two `.bat` launchers never ask (each pins `-Variant`).
- Version picker (Chinese): Enter = `latest`, `b`/`beta` = newest `beta-*` prerelease (resolved via the GitHub API), a bare `YYYYMMDD.HHMM` = `build-<ts>`, or an explicit tag (`build-…` / `beta-…`). `install.cmd` without `AGENT_DEVBOX_RELEASE_TAG` downloads the latest script zip so this prompt still runs; with an explicit tag it passes `-ReleaseTag` and skips the prompt.
- Idempotent: creates only what is missing. Re-running with an existing distro asks whether to re-import it; the prompt is `[Y/n]` so Enter means **reinstall**. `-Reinstall` forces it for unattended runs; `-Yes` stays idempotent (no reinstall unless `-Reinstall`). The data-disk VHDX is never touched/reformatted.
- Disk-space pre-check runs **before** any download (`Assert-DiskSpace`, step `[2/10]`): `required = base + 2 GiB data-disk reserve + max(3 GiB, 10% of base)`; the streaming tier uses `base = C + V` (`C` = compressed parts, `V` = uncompressed × 1.05; the `ext4.vhdx` grows on demand). The uncompressed size is parsed from the zstd frame header (local byte read, or an 18-byte HTTP Range request for the remote part). Re-run whenever it falls back to a higher-peak tier.
- Import is tiered: **Tier 1** streams the downloaded parts straight into `wsl --import <Distro> <InstallDir> -` (no `zstd.exe`, no merged `.zst`, no `.tar`; WSL2's bsdtar decodes zstd), **Tier 2** `Join-Parts` then imports the `.tar.zst` by file path, **Tier 3** (last resort) fetches a pinned `zstd.exe` and decompresses to `.tar`. The happy path never downloads `zstd.exe` on Windows 11 or 10.
- After import, `Assert-DistroReady` asserts the distro is really registered (exact name via `wsl -l -q`, `ext4.vhdx` exists, it launches); on failure it unregisters the partial registration and throws a Chinese message with the per-user caveat (UAC into a different admin account = `WSL_E_DISTRO_NOT_FOUND`). Parts / merged `.zst` / `.tar` are cleaned up on success and failure.
- Shared helpers live in `wsl-ensure.ps1` (side-effect-free, no `param()` block), dot-sourced by `install-agent-devbox.ps1` and `import-distro.ps1`; the pure ones are unit-tested by `tests/powershell/run.ps1`.
- **Lazy-load seam (download helper):** `wsl-ensure.ps1` records its own directory once at load time in `$script:AgentDevboxEnsureDir = $PSScriptRoot` (so resolution works no matter which caller dot-sourced it). `Get-AgentDevboxDownloadHelperPath` joins that directory with `wsl-ensure-downloads.ps1` and throws a clear Chinese error if the Release zip was not fully extracted. The helper is dot-sourced **only** inside `Ensure-Wsl`'s wsl-ui branch and the `Get-ZstdExe` wrapper; the happy path (WSL present, Tier 1 streaming import) never loads it, so the always-loaded working file carries no download-and-execute shape.
- Data-disk lifecycle: `New-VHD` (diskpart fallback) → `wsl --mount --vhd --bare` → run `/usr/local/bin/datadisk-init.sh <label>` with the ext4 label `devbox-data` → capture UUID → `wsl --unmount`. Writes 5 keys to `/etc/agent-devbox.conf` (`DATA_VHDX`, `DATA_UUID`, `PASEO_PASSWORD`, `DATA_MNTNAME`=`devbox-data`, `DATA_TASK`) and **always** registers the hidden **attach-only** logon task (`RunLevel Highest`, `AtLogOn`, `MultipleInstances IgnoreNew`; action a hidden PowerShell `-WindowStyle Hidden -EncodedCommand` running `wsl.exe --mount --vhd "<path>" --bare` — no `--type ext4`, no `--name`; per-variant names `agent-devbox-mount-datadisk` / `agent-devbox-core-mount-datadisk`); `-NoTask` skips it. Also copies the `mount-datadisk.*` / `unmount-datadisk.*` helpers into the InstallDir. Boot is pure Linux: `wsl-boot.sh` finds the attached device by UUID (`blkid -U`) and `mount -t ext4` it at `/mnt/devbox-data` — it never calls `wsl.exe`/`schtasks.exe`.

## ANTI-PATTERNS
- NEVER build a `cmd /c copy /b "..."` command string (quote/`$()` escaping breaks the PS parser) — use `Join-Parts`.
- NEVER move the disk-space check (`Assert-DiskSpace`) after the download; the ps-lint tripwire enforces disk-check-before-download.
- NEVER make the happy path download `zstd.exe`: Tier 1 streaming into `wsl --import -` must be tried first, and `zstd.exe` is the last-resort tier only.
- NEVER default the reinstall prompt to no (`[y/N]`); Enter must mean reinstall (`[Y/n]`), and `-Yes` must stay idempotent (no reinstall unless `-Reinstall`).
- NEVER leave the installer's output only in the elevated window; the log relay must echo it back to the original window, and the `.bat` launchers must `pause` so the result stays on screen.
- NEVER format an existing data disk; re-running the installer only refreshes config.
- NEVER let the boot script call Windows tools (`wsl.exe` / `schtasks.exe`): that re-entered WSL from `/etc/wsl.conf [boot] command` and caused a boot loop. Windows only **attaches** (the hidden logon task); Linux does the `mount -t ext4`.
- NEVER change the scheduled-task action to `--type ext4 --name`: the logon task must stay attach-only (`wsl --mount --vhd "<vhdx>" --bare`), and the Linux boot does the mount.
- NEVER make the scheduled-task action visible: it must stay hidden (`-WindowStyle Hidden -EncodedCommand`) so no blank console window flashes.
- NEVER stage or execute installer scripts from `%TEMP%` — use `%LOCALAPPDATA%\agent-devbox` and clean the per-run directory on every path.
- NEVER reintroduce `Add-Type -TypeDefinition`, `DllImport`, raw `HttpWebRequest` or `GetResponseStream` in `wsl-ensure.ps1`; the CI tripwires reject them and they are the strongest PS.NetLoader heuristic signals.
- NEVER keep a truncated part: a short download must fail and resume. `Save-Download` uses `curl.exe` (which verifies Content-Length and exits non-zero on a short read) with `-C -` resume, falling back to `Invoke-WebRequest`; an incomplete part silently kept is what breaks the merge/import.
- NEVER put a runnable web one-liner in `install.ps1`; it is a legacy in-memory entry only, and the recommended local entry is `install.cmd`.
- NEVER ship `install.ps1` in the release zip — the zip carries `install.cmd`, the `.bat` launchers and the `-File`-loaded `.ps1` files.
- NEVER add a download-and-execute helper to `wsl-ensure.ps1`; `Install-WslUi` and `Get-ZstdExeFromRelease` live in the lazily loaded `wsl-ensure-downloads.ps1`, resolved via `Get-AgentDevboxDownloadHelperPath`, and the happy path never dot-sources it. `Get-ZstdExe` stays a thin wrapper with the same name/signature, so Tier 3 callers are unchanged.
- NEVER add a BOM to `install.ps1` (a BOM survives an in-memory fetch as U+FEFF and breaks PS 5.1 parsing); NEVER strip the BOM from the other `windows/*.ps1` (PS 5.1 `-File` would garble the Chinese).
- NEVER add non-ASCII to the `.bat` or `.cmd` files — Chinese belongs in the `.ps1` (cmd reads a BOM-less file as ANSI); keep `.cmd` at CRLF line endings.
- NEVER build a second elevation path — the `.bat` self-elevate and the `.ps1` self-invoke are the only ones.
- The interactive shell user is root; the paseo daemon runs as non-root `paseo`.
