# scripts/ — runtime boot logic

## OVERVIEW
Bash that boots the environment in both modes; runs as root, copied to `/usr/local/bin` at build time, shared by Docker and WSL.

## WHERE TO LOOK
| File | Role |
|---|---|
| paseo-boot.sh | single owner: pins a sane `PATH` at the top (the WSL `[boot]` env is minimal — no `/usr/bin`, so `gosu ... env` failed with `executable file not found in $PATH` and the daemon never started); verifies the **Supervisor's own JSON lock** (`$PASEO_HOME/paseo.pid`: pid+startedAt+bootId+uid, `/proc/<pid>` real/effective uid, comm `Paseo Superviso`, title `Paseo Supervisor`, image node exe, kernel starttime) before starting and drops it only when re-read unchanged and proven dead/cross-boot/PID-reused (a live lock or a briefly empty write is kept; the recorded PID is never signalled); parses `PASEO_LISTEN`/`PASEO_WEB_UI_ENABLED` ONCE via `paseo-env.sh` (invalid → FATAL before lock/seed/daemon) and uses the canonical values for both `daemon config set` and the `daemon run` env; drops to `paseo` and runs `paseo daemon run`; enforces `PASEO_PASSWORD`; `flock -n -E 75` single-instance (exit 75 = held → "already running" rc 0, any other rc → FATAL, never conflated); verifies top-level paseo home + `/workspace` owner by numeric `uid:gid` from `_paseo_uid`/`_paseo_gid` (`stat` first, `chown` + re-stat only when wrong; home missing/chown/verify failure → FATAL before seed, workspace only WARN); then, as `paseo` via `gosu paseo env HOME=<paseo home>`, reads `git config --global --get-all safe.directory` and adds `/workspace` only when the exact line is absent (idempotent; never root's global config and never `--replace-all`; missing git or any git failure only WARNs before seed/daemon); test seams `AGENT_DEVBOX_PASEO_HOME_DIR`/`_WORKSPACE_DIR`/`_STAT_BIN`/`_CHOWN_BIN`/`_FLOCK_BIN`/`_GIT_BIN`. ## CONVENTIONS
- All scripts: `set -euo pipefail`; shellcheck 0.9.0-clean (no `A && B || C`). **Exceptions:** `wsl-boot.sh` deliberately uses `set -uo pipefail` (no `-e`) — its boot logic is best-effort and a failed step must not abort before it logs / writes the MAINTENANCE MOTD; `desktop-cli-check.sh` uses the same for the opposite reason — every probe must report instead of aborting the run, and it never writes anything itself; `wsl-session-mount.sh` also omits `-e` so every skip/failure prints its own warning before `exit 3`/`4`; `paseo-env.sh` is sourced by both boot scripts and tests, so it intentionally sets NO shell options and produces no output on success.
- paseo-boot: sets `HOME=/home/paseo` for the daemon ONLY; verifies and only-if-needed chowns the top-level home/workspace by numeric `uid:gid` and re-stats (never recurse the mounted data disk); home failure is fatal, workspace failure warns. The daemon's pidfile is on that persistent home, so it is **validated against `/proc` identity and bootId** (dead, cross-boot, or reused PID → delete; live Supervisor → keep) before every start.
- wsl-boot exports the standard `PATH` at load: `[boot]` provides none, and children (`setsid` -> execvp) fail with ENOENT on a relative name. Executables started by children are resolved to **absolute** paths (`dockerd` via `command -v`). Mount identity uses `findmnt … | sort -u` so a boot race that stacks the same device twice is not mistaken for a UUID mismatch.
- wsl-boot logs to **stdout only**: `/etc/wsl.conf [boot] command` already redirects into `/var/log/agent-devbox-boot.log` (`>>`), so appending in the script too wrote every line twice.
- wsl-boot: idempotent; **self-attaching** — when the data device is absent it makes exactly one bounded `wsl.exe --mount --vhd <path> --bare` call, then locates the block device by UUID (`blkid -t UUID=`), falling back to the **per-channel** label (`blkid -t LABEL=$DATA_LABEL`; stable `devbox-data` / beta `devbox-data-beta`), fails closed when more than one attached device matches, and `mount -t ext4` it at `/mnt/<DATA_MNTNAME>` (i.e. `/mnt/devbox-data`); it NEVER calls `schtasks.exe` / `wsl -d` / `--unmount` (the old boot-time callback re-entered WSL and caused a boot loop). Verifies the mount with `findmnt` (+ UUID when `DATA_UUID` is set). The overlay marker decides whether dockerd is required (never `command -v`). After mount/UUID/bind ONE 30s deadline is shared by every required service; success needs the Supervisor lock identity + `/api/health` 200 (and identified dockerd + `docker info` with the marker) in the same round, then `clear_motd` and exactly one `boot complete`. A service failure writes a DIFFERENT bilingual `/etc/motd` (`数据盘已挂载；<服务> 未就绪。`, reason, log), never the disk-repair banner. A data-disk failure prints MAINTENANCE MODE, logs `boot failed`, and writes a bilingual `/etc/motd` banner with the copy-pasteable repair commands: first for the WSL terminal (`cmd.exe /c "<InstallDir>\mount-datadisk.cmd"`, `wsl.exe --terminate <distro>`), then the Windows PowerShell fallback (`<InstallDir>\mount-datadisk.cmd`, `wsl --terminate <distro>`), then exits before seeding/starting — it NEVER auto-launches the Windows installer; on success it clears the stale banner. Reads 6 keys from `/etc/agent-devbox.conf` (`DATA_VHDX`, `DATA_UUID`, `PASEO_PASSWORD`, `DATA_MNTNAME`, `DATA_DISTRO`, `DATA_LABEL`); label precedence `AGENT_DEVBOX_DATA_LABEL` (env, snapshotted, re-applied after the source) > conf `DATA_LABEL` > `devbox-data`, and labels are per channel (`devbox-data` stable / `devbox-data-beta` beta). Its constants are env-overridable (`AGENT_DEVBOX_CONF` / `_DATADIR` / `_OPENCODE_BIN` / `_ATTACH_TIMEOUT` / `_DEVICE_WAIT` / `_PASEO_LOG` / `AGENT_DEVBOX_MOTD`) so tests can source it. Logs to stdout only (`/etc/wsl.conf` already redirects into the log). After the binds it calls `ensure_opencode_shim /root /home/*`: the OpenCode DESKTOP app probes ONLY `$HOME/.opencode/bin/opencode` (no PATH lookup) and needs that path to run `serve`, but `/root` and `/home` live on the data disk, so the link is (re)created every boot; it never overwrites an existing executable CLI and never installs V2.
- seed-agent-config.sh honors `AGENT_SEED_DIR` (default `/opt/agent-seed`) so tests can point it at a temp dir.
- datadisk-init.sh refuses unless exactly one whole, partition-less, filesystem-less, non-root disk is found; it takes the **channel-specific** ext4 label as `$1` (stable `devbox-data` / beta `devbox-data-beta`) and validates it (non-empty, `[A-Za-z0-9._-]`, ≤16 chars) before `mkfs -L`.

## ANTI-PATTERNS
- Boot scripts must NEVER format a disk.
- Boot scripts may make **exactly one** Windows call: the bounded `wsl.exe --mount --vhd <path> --bare` attach. NEVER call `schtasks.exe`, `wsl -d` or `--unmount` from `/etc/wsl.conf [boot] command` — re-entering WSL caused a boot loop.
- `wsl-session-mount.sh` must stay interop-free: NEVER call `wsl.exe` / attach / unmount / format, and NEVER mount the data disk under `/mnt/wsl` (cross-distro leak); only a second **RW** mount of the same ext4 is allowed (never RO).
- Never set a global HOME; never `chown -R` over the mounted data disk.
- Never `|| true` away a check that guards user data or the password gate.
